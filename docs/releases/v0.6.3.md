# Hum 0.6.3

Hum 0.6.3 adds a stable CLI contract for project-defined runtime switching.
Projects can keep checkout, routing, and transition policy in their own adapter
while exposing one consistent Hum command to developers.

## Highlights

- Add `hum PROJECT TEMPLATE switch MODE [SERVICE...]`.
- Select multiple services additively or use `--all` for every target supported
  by the project adapter.
- Use `--no-start` when the new selection should be persisted without starting
  the selected template.
- Declare an optional version 3 `switch_provider` as direct argv, without shell
  interpolation.
- Execute the provider from the project root with inherited terminal streams.
- Reject unknown named services and services outside the selected template's
  resolved dependency set before invoking the provider; return a dedicated
  non-zero exit code when the adapter fails.

## Adapter contract

Given this configuration:

```yaml
switch_provider:
  command: [./scripts/runtime-switch]
```

Hum appends the mode and selected service names, followed by `--all`,
`--template NAME`, and `--no-start` when present. Modes remain project-defined,
so the same CLI can support source checkouts, container images, status views, or
future runtime strategies without product-specific logic in Hum. Adapter argv
is trusted configuration: multi-component executable paths resolve from the
project root, and absolute or parent-relative paths may be used for shared
adapters outside that directory.

Modes may also be invoked without a service selection for adapter-owned
operations such as status. Because modes are project-defined, each adapter
decides which mutating modes require explicit names or `--all`.

## Upgrade notes

`switch_provider` requires configuration version 3. It is optional, so existing
projects continue to work unchanged. Projects that do not declare an adapter
receive an actionable configuration error if `switch` is requested.
