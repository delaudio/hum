# Homebrew distribution

Hum releases native macOS archives for Apple Silicon and Intel. Each archive
has a SHA-256 sidecar and build metadata tied to the tagged commit and workflow
run. The release workflow renders a formula with those exact checksums, installs
it on both architectures, and only then updates the public tap.

## User installation

Once the tap has been bootstrapped, installation is one command:

```bash
brew install delaudio/tap/hum
```

Upgrade and uninstall use normal Homebrew commands:

```bash
brew upgrade hum
brew uninstall hum
```

## One-time tap bootstrap

The standard short tap name `delaudio/tap` maps to the public GitHub repository
`delaudio/homebrew-tap`. Create that repository once with a `Formula/`
directory, then configure the Hum repository with:

- a fine-grained `HOMEBREW_TAP_TOKEN` Actions secret granting Contents
  read/write access to `delaudio/homebrew-tap`;
- a repository Actions variable named `HOMEBREW_TAP_ENABLED` set to `true`.

Until both are present, releases and their Homebrew smoke tests still complete;
only the cross-repository tap update is skipped.

## Publishing a release

1. Update the package version in `Cargo.toml` and `Cargo.lock`.
2. Run the repository quality gates.
3. Tag the exact release commit with `v<semver>` and push the tag.
4. Wait for the `Release` workflow to publish and smoke-test the artifacts.

The workflow rejects a tag whose version does not match `Cargo.toml`. Release
archives and formula checksums are generated by the same run; the formula never
uses `sha256 :no_check`.

For the initial package version:

```bash
git tag -a v0.1.0 -m "hum v0.1.0"
git push origin v0.1.0
```
